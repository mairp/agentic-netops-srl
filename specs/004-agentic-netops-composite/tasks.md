# Tasks: Agentic NetOps on Nokia SR Linux — Composite Platform

**Input**: Design documents from `/specs/004-agentic-netops-composite/`

**Prerequisites**: plan.md, spec.md, research.md (D-01…D-37, RD-01…RD-15, CD-01…CD-06, AD-01…AD-82), data-model.md,
contracts/ (13 files), quickstart.md, traceability.md, platform-coupling.md, evidence/

**Tests**: INCLUDED. The specification requests them explicitly (FR-020, NFR-013, SC-001…SC-050,
constitution Principle VI). Offline tests in a story are written first and MUST fail before the
implementation they cover; live checks close each story.

**Organization**: by user story. US3 is retired (RD-04) and has no phase; its number is not reused.
Plan delivery phases P0–P12 are mapped onto stories in the header of each phase below. Two ordering
rules from plan.md override plain priority order and are encoded in the phase sequence:

1. **The safety boundary is built and proven before any agent workload is deployed** — so US6
   (Phase 5) precedes US7, US4 and US5 although all are P1. Plan phase *numbers* are identities, not
   a schedule: the execution order is P0 → P2 → P3 → P1 → P6 …, recorded in plan.md §Delivery phases
   (AD-08), and the invariant is enforced mechanically by T073.
2. **`README.md` is the last task of the list** (P12 / C-22 / CD-06) — so the closing phase ends with
   it and nothing follows it.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: US1…US13 (US3 retired); Setup, Foundational and the two closing phases carry none
- Every task names the file(s) it creates or changes; contract and data-model sections are cited as
  `contracts/<file> §n` / `data-model.md §n` and are relative to `specs/004-agentic-netops-composite/`

## Constitution-Driven Task Categories

Tagged inline as **[Truth]**, **[Gate]**, **[Txn]**, **[Obs]**, **[Pin]**, **[Test]** (constitution
v1.1.0, Principles I–VI):

- **[Truth]** status from verified live state; two-sided keyed read-back; scheduled re-verification
- **[Gate]** two confirmations; refusals that enumerate alternatives; authentication; boundary denials
- **[Txn]** translate → server-side dry-run → apply → rollback → watch; idempotence; nothing stranded
- **[Obs]** gNMIc → OTLP → collector → Prometheus → Grafana; conditions, Events, structured logs
- **[Pin]** `versions.lock.yaml`, `make verify-pins`, local image builds
- **[Test]** unit/golden/envtest/gate/integration/e2e; MTU-sized probes (9320/9300); run-captured
  evidence with a negative control for every readiness check

## Path Conventions

Repository root is `/root/agentic-netops-srl`. Layout is plan.md §Project structure: Go under `api/`,
`cmd/`, `controllers/`, `pkg/`, `internal/`, `config/`; lab under `lab/`; manifests under `deploy/`;
Python tier under `agents/`; browser app under `ui/`; tests under `tests/` (Go, shell) and
`agents/tests/` (Python); lifecycle under `scripts/`. The root `config/` is Go/cluster assets only —
the Python config package is `agents/config/`. There is no `config/upstream/` (FR-098).

Four directories were added by task generation and are now in plan.md's tree: `pkg/kuid/` (the one
claim-adapter seam of C-13/CD-03), `internal/webhook/` (the cross-object admission rules of
contracts/crd-api.md), `scripts/ci/` (the `verify-*` checks behind the `make` interface) and
`docs/{reference,operations}/` (C-19). `tests/lib/` — the shell helpers the verification tools share,
`leftovers.sh` first (T043) — came with the fifth pass and joined the tree and T001 with the sixth (AD-57).

**Task ids are stable and are not a schedule.** T165–T169 were added by the analysis remediation of
2026-09-20, T170–T172 by its second pass the same day (FR-109, SC-045), and T173 by its third
(SC-046; AD-16…AD-22 otherwise amended existing tasks in place), and T174 by its fourth
(AD-24, AD-26; AD-23…AD-30 otherwise amended existing tasks in place), and T175 by the operator

their work belongs, out of numeric order by design. T176–T183 were added on 2026-09-21 when the first
implementation run stopped on G11 and the first-party allocation authority was adopted by recorded
decision (`docs/decisions/allocator-substitution.md`, AD-74); they sit in User Story 1, before T048,
because provisioning cannot pass `AppsReady` without an authority. **T164 remains the last task.**

**Hard rules that apply to every task** (do not restate, do not violate):

- Never invent a digest, version, timing or count. Digests are resolved from registries by tooling
  (T010); a value not yet observed is left unresolved and the pin check fails on it (NFR-003).
- The denied management port set is stated **once**, in contracts/kubernetes-objects.md §"Identity
  contract", and every other mention cites it; a task never retypes it (FR-075, SC-029).
- One southbound: provider → SDC `Config` → gNMI/TLS 57400. No executor, no host-side writer, no
  second renderer, no look-alike CRD in an upstream group (FR-007, FR-014, FR-098). The only other
  things that may touch a lab device are the **verification tools** FR-108 names — the gate, fault
  and drift injection, the walkthrough's read-only proofs — and only as FR-108 bounds them:
  through `evidence_run`, scratch or a declared fault only, removed by the tool that wrote it with
  the removal read back, and with nothing the platform does depending on it. A device client
  anywhere else fails `make verify-boundaries` (T025).
- Every bound and interval has one default, in data-model.md §25; a task that implements a bound
  asserts that default and that its override is honoured.
- Native `srl_nokia` paths only, each covered by the path register (FR-017).
- FR/NFR/SC/R/RD/CD/G identifiers are stable; retired ids keep their tombstones.
- `checklists/requirements.md` and `checklists/clarify-delta.md` are reviewer-owned: never tick an
  item in either.
- Status of spec artefacts stays Draft until something is observed (Principle I).

## Implementation Strategy

### MVP First (User Story 1 only)

1. Phase 1 → Phase 2 → Phase 3.
2. **STOP and VALIDATE**: clean-host bring-up, the gate record with its negative controls, the
   converged default `Fabric`, idempotent re-run, ownership-scoped teardown.
3. Read the qualification record before going further — it decides what later stories refuse by
   name (egress ACL, IPv6 anycast gateway / IPv6 Type-5) and, through G11, whether the allocator
   branch of CD-03 needs an **operator decision**. The script never makes that decision.

### Incremental Delivery

1. US1 → a reproducible, qualified lab (MVP).
2. + US2 → a declarative control plane with truthful status — complete and useful with no tier.
3. + US6 → the proven boundary. + US7 → a healthy, authenticated, removable tier.
4. + US4 → three constructs from plain language. + US5 → the fourth. **All P1 done.**
5. + US8, US9, US10, US11, US12 (parallelizable) → + US13.
6. Phase 15 gates; Phase 16 closes with `README.md`.

### Stop-and-ask points (the operator's, never the build's)

- **Standing delegation (AD-82, 2026-09-21)**: a live finding that contradicts an assumption is decided by the build in favour of the requirement's intent, recorded in `docs/decisions/live-findings.md` with its evidence, and the run continues. The build still stops — **once; it does not repeat the pass** — where the only ways forward waive or weaken a gate, relax a requirement, add a pin exception, touch what the platform does not own, need a credential it was not given, or are outward-facing. The points below are those.
- **G11 fails** → *(this happened on 2026-09-21 and the decision is recorded: AD-74, T176–T183; the rule below stands for the substitute too — there is no third authority.)* provisioning stops; adopting the first-party allocator needs
  `docs/decisions/allocator-substitution.md` citing the failed evidence by path and SHA-256, and the
  lock-file change. Until then, do not implement the substitute controller — it has **no task on
  purpose**; once the decision is recorded, `/speckit-converge` adds its tasks with fresh ids before
  Phase 16. The same stop applies if only G11's stated-value half fails (FR-109, R-44).
- **A walkthrough take fails acceptance** → delete, report verbatim; a second take needs new
  identifiers and a human decision.
- **The video asset upload and the repository slug/badges** → handed over, not performed.
- **The Go module path's owner** (T002) and **the CODEOWNERS reviewer handle** (T165) → confirmed by
  the operator before the first push; neither is guessed.
- **The two model providers of SC-022** (T144) and their credentials → the operator's to name and
  supply; if either is a gateway it is declared as one, with its base URL (FR-106).
